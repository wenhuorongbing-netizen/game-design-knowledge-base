# Use This First

This is the shortest entry point for using the Game Design Knowledgebase as an AI Game Design Master.

## What Is This Project?

This is a source-governed Game Design Knowledgebase. It helps an AI reason about game design domains, ask better questions, choose lenses and workflows, and produce useful design artifacts.

It is not an app, not BookOS, not a reading tracker, not a forum, and not a private book parser.

## What Can I Do With It Today?

You can use it to:

- shape a vague game idea;
- ask for a design review;
- learn game design concepts;
- create a source-safe reading plan;
- generate draft design artifacts;
- ask what evidence would be needed before a claim becomes stronger;
- make an AI label assumptions, `source_basis`, confidence, and evidence gaps.

## What Can I Not Do Yet?

You cannot honestly use it to:

- claim verified book doctrine without EvidenceRefs;
- summarize private or high-risk book files;
- extract quotes from source files;
- invent user notes, legal sidecars, project facts, playtest results, telemetry, or benchmark outputs;
- treat draft KB scaffolding as verified knowledge.

## I Want To Learn Game Design. What Can I Do?

Use [USE_CASES/learn_game_design.md](USE_CASES/learn_game_design.md).

Ask the AI to teach one topic at a time and include:

- simple explanation;
- when to use it;
- when not to use it;
- diagnostic questions;
- a small exercise;
- source/confidence labels.

## I Want AI To Review My Idea. What Do I Paste?

Paste this:

> Use the Game Design Knowledgebase as an AI Game Design Master runtime. Treat the KB as draft/source-governed scaffolding unless evidence exists. Review my idea and produce a one-page concept memo. Include core experience, player fantasy, design pillars, risks, useful lenses, one workflow, assumptions, `source_basis`, confidence, evidence gaps, and one next action.
>
> My idea: [write your idea here]

For more copy-paste prompts, use [HANDS_ON_PROMPT_LIBRARY.md](HANDS_ON_PROMPT_LIBRARY.md).

If you want to see what a safe output looks like before trying it, open [WORKED_EXAMPLES_README.md](WORKED_EXAMPLES_README.md).

## What Files Should I Ignore First?

Use [WHAT_TO_IGNORE_FIRST.md](WHAT_TO_IGNORE_FIRST.md).

In short, ignore generated exports, audits, benchmark internals, schemas, legacy folders, evidence internals, private sources, and deprecated material unless you are maintaining or verifying the KB.

## What Is The Shortest Path To Hands-On Use?

4. Paste your idea or question.
5. Ask for one artifact.
6. Require assumptions and confidence labels.
