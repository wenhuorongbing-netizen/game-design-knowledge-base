# No-Project Portfolio Artifacts

Date: 2026-04-30

## Purpose

This file lists useful artifacts a learner can create before having an active game project.

These artifacts show design thinking, not verified source-backed knowledge.

## Artifact Index

| Artifact | What it demonstrates | Source/confidence |
|---|---|---|
| one-sentence concept | ability to frame player, action, goal, and feeling | unsupported_draft / weak |
| core experience statement | ability to define player promise and repeated action | unsupported_draft / weak |
| meaningful choice matrix | ability to detect information, tradeoff, consequence | unsupported_draft / weak |
| formal rule table | ability to specify actions, goals, boundaries, outcomes | unsupported_draft / weak |
| simple resource loop map | ability to identify sources, sinks, feedback risks | unsupported_draft / weak |
| UI feedback redesign | ability to improve signal timing and readability | unsupported_draft / weak |
| narrative-mechanic alignment map | ability to connect story promise to player action | unsupported_draft / weak |
| paper prototype rule set | ability to reduce a design question to playable rules | unsupported_draft / weak |
| hypothetical playtest plan | ability to plan observation without inventing results | unsupported_draft / weak |
| pitch critique memo | ability to assess promise, scope, proof gaps | unsupported_draft / weak |
| unsupported claim check | ability to prevent overclaiming and citation misuse | unsupported_draft / weak |
| learning reflection note | ability to separate assumption, interpretation, and evidence gap | user_interpretation / weak |

## Portfolio Folder Suggestion

Create a local folder outside canonical KB records if you want to save drafts:

- `learning_artifacts/`
- `concepts/`
- `decision_matrices/`
- `system_maps/`
- `prototype_plans/`
- `reflections/`

Do not commit private notes or copyrighted source excerpts unless they are source-governed and intentionally added.

## What Makes A Good No-Project Artifact

A good artifact is:

- small;
- specific;
- testable later;
- clear about assumptions;
- clear about what it does not prove;
- reusable as a future project starting point.
