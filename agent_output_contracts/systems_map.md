# Output Contract: Systems Map

## Artifact Purpose

Represent system parts, loops, resources, dependencies, and feedback paths.

## Required Sections

- system boundary;
- parts;
- player actions;
- resources;
- loops;
- feedback paths;
- risk points;
- next test.

## Required Labels

- assumptions;
- `source_basis`;
- confidence;
- evidence gaps;
- next action.

## Quality Criteria

The map must expose interactions, not just list features.

## Source/Confidence Rule

Do not invent telemetry or player behavior.

## Common Failure Modes

- feature list only;
- missing loops;
- invented numbers;
- no test.

## Done Criteria

The user can identify which loop to tune or test first.
