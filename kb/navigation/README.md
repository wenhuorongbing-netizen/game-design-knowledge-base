# Game Design Knowledgebase Navigation

This folder is the human entry layer for the Game Design Knowledgebase. It does not add app features, user accounts, forum behavior, or source ingestion. It only points people to existing KB assets.

## Start By Role

| Role | Path | Use When |
|---|---|---|
| Learner | [learner_path.md](learner_path.md) | You want a structured learning sequence from fundamentals to production. |
| Working designer | [designer_path.md](designer_path.md) | You have a design problem and need a workflow, lenses, cards, and output artifact. |
| Researcher | [researcher_path.md](researcher_path.md) | You need to understand source_basis, confidence, evidence, claims, and legal boundaries. |
| Maintainer | [maintainer_path.md](maintainer_path.md) | You need to add or validate KB material without breaking governance. |
| Source governance reviewer | [source_governance_path.md](source_governance_path.md) | You need to audit high-risk sources, legal sidecars, and evidence safety. |
| Quick problem solver | [quick_problem_solver.md](quick_problem_solver.md) | You know the symptom and want the fastest safe starting point. |

## Navigation Rules

- Treat cards, lenses, workflows, lessons, and exercises as draft scaffolds unless their `source_basis`, `confidence`, and `evidence_refs` say otherwise.
- Related works are routing metadata, not proof that a book says something.
- High-risk source files remain metadata-only unless a legal sidecar explicitly permits processing.
- Prefer workflow packs when you need an output artifact.
- Prefer lenses when you need diagnostic questions.
- Prefer cards when you need vocabulary and evidence slots.
