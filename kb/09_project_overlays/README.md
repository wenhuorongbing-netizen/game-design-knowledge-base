# Project Overlays

This folder keeps project-specific application separate from the general Game Design Knowledgebase.

- Status: canonical application layer
- Users: designers, producers, researchers, maintainers
- Edit: yes, carefully
- Updated by: manual project records, then `npm run kb:export`

## Purpose

General KB cards, lenses, workflows, lessons, and claims must remain reusable. Project overlays record how those general assets were applied to a specific game project, prototype, design audit, or playtest.

## Folders

- `overlays/`: ProjectOverlay entities.
- `playtest_logs/`: PlaytestLog entities.
- `project_overlay_template.md`: template for a new overlay.
- `playtest_log_template.md`: template for a new playtest log.
- `PROJECT_APPLICATION_GUIDE.md`: rules for applying general KB assets to a project.

## Governance

- Do not write project conclusions back into general cards without evidence and review.
- Do not treat a project result as a universal game design rule.
- Keep source_basis, confidence, evidence_refs, assumptions, and evidence gaps explicit.
- Keep high-risk source files metadata-only.
