# EX08 - Prototype Plan Example

Labels: demo_only, synthetic_example, not_user_evidence, not_project_evidence, not_benchmark_result, not_verified_claim.

## User Input

I want to test whether lighthouse repair and spirit relationships can work together in a small prototype.

## Prompt Used

[P10_make_prototype_plan.md](../hands_on_prompts/P10_make_prototype_plan.md)

## Example AI Output

| Field | Synthetic output |
|---|---|
| prototype question | Does completing a repair feel more meaningful when it changes a spirit interaction and the environment? |
| minimum scene | One beach, one lighthouse room, one spirit, one broken light mechanism. |
| required actions | gather one resource, choose repair, talk to spirit before and after repair. |
| feedback needed | visible light change, spirit response change, one environment safety change. |
| success signal | Player can explain why repair mattered beyond checklist completion. |
| excluded scope | full economy, multiple spirits, full day cycle, combat, inventory depth. |
| output artifact | prototype test card with question, features, excluded scope, and observation checklist. |

## Why This Output Is Useful

It prevents overbuilding by tying the prototype to one clear question.

## Assumptions

- The user can build or mock one small scene.
- The repair and spirit interaction can both be represented simply.
- The goal is learning, not production polish.

## What This Example Does Not Prove

It does not prove the design works. It defines a safe test to learn whether it might work.

## How User Can Adapt It

State one uncertainty, one mechanic, one feedback moment, and one thing you will intentionally exclude.
