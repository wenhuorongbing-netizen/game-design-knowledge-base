# No-Project 30-Day Hands-On Plan

Date: 2026-04-30

## Purpose

This 30-day plan extends the 7-day plan into a practical first month of game design learning without requiring an active game project.

It is organized by weekly capability focus and daily artifact production.

## Week 1 - Foundations And Core Experience

| Day | Task | AI prompt focus | Artifact | Note |
|---|---|---|---|---|
| 1 | Create five one-sentence game concepts. | generate design questions | concept list | why one concept is strongest |
| 2 | Pick one concept and define player promise. | define core experience | player promise | what is assumed |
| 3 | Define repeated player action. | core loop question | repeated action statement | what action may become boring |
| 4 | Create design pillars. | review game idea | three design pillars | what each pillar excludes |
| 5 | Identify risks. | lens review | risk memo | what evidence would reduce risk |
| 6 | Create smallest prototype question. | prototype plan | prototype question sheet | what not to build yet |
| 7 | Reflect and revise. | learning coach | revised concept memo | what changed |

## Week 2 - Rules, Choices, And Systems

| Day | Task | AI prompt focus | Artifact | Note |
|---|---|---|---|---|
| 8 | Define player verbs. | generate design questions | verb list | strongest verb |
| 9 | Create a simple rule table. | design audit | formal rules sheet | unclear rule |
| 10 | Make a meaningful choice matrix. | meaningful decision audit | decision matrix | fake-choice risk |
| 11 | Add information and consequences. | meaningful decision audit | consequence map | what player must know |
| 12 | Map one resource loop. | systems/economy audit | source/sink map | inflation or starvation risk |
| 13 | Cut unnecessary parts. | systems audit | feature cut list | why each cut helps |
| 14 | Reflect and revise. | learning coach | rules and systems memo | what remains uncertain |

## Week 3 - Feedback, Feel, UI, Narrative

| Day | Task | AI prompt focus | Artifact | Note |
|---|---|---|---|---|
| 15 | Diagnose a feel problem in a known game. | game feel audit | feel audit table | what you observed |
| 16 | Redesign one feedback signal. | UI feedback audit | feedback redesign | why timing matters |
| 17 | Audit information priority. | UI feedback audit | UI priority list | what players need first |
| 18 | Align one story promise with one action. | narrative-mechanic alignment | alignment map | where story and action conflict |
| 19 | Define role and player identity. | design questions | player role statement | what the player is allowed to be |
| 20 | Create a small exercise from the week. | generate exercises | original practice exercise | what it trains |
| 21 | Reflect and revise. | learning coach | feedback/narrative memo | what needs testing |

## Week 4 - Prototype, Playtest, Pitch, Source Safety

| Day | Task | AI prompt focus | Artifact | Note |
|---|---|---|---|---|
| 22 | Write a paper prototype component list. | prototype plan | component list | what is excluded |
| 23 | Write paper prototype rules. | prototype plan | paper rule set | likely loophole |
| 24 | Create a playtest plan for the hypothetical prototype. | playtest plan | playtest script | what would count as signal |
| 25 | Create an observation sheet. | playtest plan | observation sheet | fact versus interpretation |
| 26 | Critique a fictional pitch. | pitch critique | pitch memo | what proof is missing |
| 27 | Detect unsupported claims. | unsupported claim check | claim safety report | safer wording |
| 28 | Create learning reflection. | learning coach | reflection note | what AI must not claim yet |
| 29 | Assemble portfolio artifacts. | design decision log | portfolio index | what each artifact demonstrates |
| 30 | Review month and choose next path. | learning coach | next-month plan | next capability to unlock |

## Month-End Portfolio

By day 30, you should have:

- one concept memo;
- one core experience statement;
- one rule table;
- one decision matrix;
- one system map;
- one feedback redesign;
- one narrative-mechanic alignment map;
- one paper prototype rule set;
- one hypothetical playtest plan;
- one pitch critique;
- one unsupported claim check;
- one learning reflection.

## Source And Confidence Rule

All 30-day artifacts are draft learning outputs unless real evidence is added later.

Default:

- source_basis: unsupported_draft
- confidence: weak
- verified claims: none
