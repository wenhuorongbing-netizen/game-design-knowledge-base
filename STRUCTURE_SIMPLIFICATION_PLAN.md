# Structure Simplification Plan

This plan makes the Game Design Knowledgebase easier to understand without deleting canonical KB content or breaking export paths.

## Current Structure

| Path | Current Role | Current Status |
|---|---|---|
| `START_HERE.md` | Human entry point | canonical |
| `kb/` | Main source-governed KB | canonical |
| `kb/11_import_export/export/` | JSON exports for search, graph, and import | generated |
| `tools/` | Authoritative importer, validator, audit, and coverage scripts | tool |
| `kb-portal/` | Static browser surface built from safe export data | optional |
| `kb-tools/` | Old legacy scripts for prior snapshot/private-source experiments | legacy |
| `50-game-design-masters-kb/` | Old snapshot from earlier KB generation | legacy |
| `docs/deprecated/` | Historical non-active instructions | deprecated |
| `_private_sources/` | Private local source quarantine | private/local |
| root audit/state reports | Current control reports | canonical |

## Problem Diagnosis

- First-time users see many root files, legacy folders, optional portal files, generated exports, and canonical KB content at the same level.
- `kb/` is canonical, but many subfolders did not clearly say whether they were source, generated, or quality output.
- `kb-tools/` and `50-game-design-masters-kb/` are still physically present, so they need visible quarantine labels.
- Generated exports are necessary for downstream tools, but users should not manually edit them.
- The safest simplification now is documentation-first labeling, not moving files.

## Proposed Target Structure

```text
START_HERE.md
  -> kb/                         canonical KB content
     -> 00_governance/           policy and contribution rules
     -> 01_sources/              source metadata and quarantine records
     -> 02_ontology/             taxonomy and entity/relationship model
     -> 03_works/                intellectual work registry
     -> 04_dossiers/             work dossier shells
     -> 05_cards/                concept/framework/application/checklist/prompt cards
     -> 06_lenses/               diagnostic design lenses
     -> 07_lessons/              learning curriculum
     -> 08_workflows/            workflow packs, exercises, prompts
     -> 11_import_export/        importer docs and generated exports
     -> 12_quality/              audits, coverage, release checks
  -> tools/                      authoritative scripts
  -> kb-portal/                  optional static browser
  -> docs/                       docs and deprecated material
  -> kb-tools/                   legacy tools to ignore by default
  -> 50-game-design-masters-kb/  legacy snapshot to ignore by default
  -> _private_sources/           ignored local private source quarantine
```

## Files And Folders To Keep

- `kb/`
- `tools/`
- root control files such as `README.md`, `START_HERE.md`, `KB_REBUILD_INSTRUCTION.md`, `VALIDATION_REPORT.md`, and `GAP_BACKLOG.md`
- `kb/11_import_export/export/` because it is required by GDKB import, search, and graph consumers
- `_private_sources/README.md` as the only tracked marker for private local source quarantine

## Files And Folders To Archive Later

No archive move is performed in this step.

Future candidates:

- old root audit reports that are superseded by `kb/12_quality/`
- `50-game-design-masters-kb/` after a separate archive or re-audit decision

## Files And Folders To Mark Generated

- `kb/11_import_export/export/`
- `kb/11_import_export/import_report.md`
- `kb/11_import_export/graph_overview.md`
- root `VALIDATION_REPORT.md`
- root `VALIDATION_REPORT.json`
- root `MIGRATION_EXCEPTIONS_REPORT.md`
- root `SOURCE_GOVERNANCE_AUDIT.md`

Generated files should be regenerated by command, not manually edited.

## Files And Folders To Mark Legacy

- `kb-tools/`
- `50-game-design-masters-kb/`

These are non-canonical unless explicitly re-audited.

## Files And Folders To Mark Deprecated

- `docs/deprecated/`

Deprecated files are historical context only. They are not active build instructions.

## Migration Risk

| Risk | Level | Mitigation |
|---|---|---|
| Breaking existing import/export paths | low | Do not move export files or canonical KB folders in this step. |
| Confusing generated README markers with KB entities | low | Add README only outside entity scan folders or rely on existing validator README exceptions. |
| Legacy tools being mistaken as active | medium | Add explicit README labels and keep opt-in guards. |
| Optional portal being mistaken as source of truth | medium | Add `kb-portal/README.md` as optional/generated-from-exports label. |
| Private source files being mistaken as ingestible | low | Keep private files under `_private_sources/` with metadata-only quarantine rules. |

## Rollback Plan

This step is reversible:

1. Remove the new README marker files if they cause confusion.
2. Keep `kb/`, `tools/`, and export paths unchanged.
3. Re-run `npm run kb:validate`.
4. If a generated export changes unexpectedly, regenerate with `npm run kb:export`.

No canonical KB data is moved or deleted in this plan.

## Acceptance Criteria

- `STRUCTURE_MAP.md` exists and shows the active repository flow.
- Folder-level README files exist for canonical, generated, optional, legacy, and tool folders named in the prompt.
- Generated exports are clearly marked as generated.
- `kb-tools/`, `50-game-design-masters-kb/`, and `docs/deprecated/` are clearly non-canonical.
- Existing export paths remain unchanged.
- `npm run kb:validate` passes.
