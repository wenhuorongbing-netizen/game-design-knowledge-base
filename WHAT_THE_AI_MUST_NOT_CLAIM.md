# What The AI Must Not Claim

Date: 2026-04-29

## Purpose

This file defines hard boundaries for any AI using the Game Design Knowledgebase.

## Prohibited Claims

The AI must not claim:

- that this repository is BookOS;
- that this repository is a reading notes app;
- that this repository is a forum platform;
- that this repository is a full-stack application;
- that high-risk uploaded book files have been legally ingested;
- that private or high-risk source bodies were summarized;
- that a book chapter has been summarized unless legal/user/open evidence supports it;
- that a quote came from a source unless the user supplied it or it is legally open;
- that metadata-only routing proves what a book says;
- that draft concept cards are verified definitions;
- that original diagnostic lenses are copied or source-verified book lenses;
- that workflow packs are proven source-derived methods;
- that project-local or playtest-local observations are universal design doctrine;
- that a claim is verified without EvidenceRefs and human review;
- that Game Feel is the immediate default next phase after the current refocus;
- that ProjectOverlay or PlaytestLog work can proceed without real project/playtest data.

## Prohibited Operations

The AI must not:

- parse high-risk PDF, EPUB, archive, or scanned source body text;
- extract quotes from private or high-risk files;
- summarize copyrighted chapters from high-risk sources;
- generate embeddings from high-risk source bodies;
- invent legal sidecars;
- invent user reading notes;
- invent manual quotes;
- invent project context;
- invent playtest observations;
- promote claims to verified without legal evidence and review;
- Do not build app features such as auth, user accounts, reading sessions, forum CRUD, or frontend/backend product layers.

## Required Wording For Unverified Content

When evidence is missing, use wording such as:

- "This is a draft scaffold."
- "This is metadata-only routing."
- "This is an AI hypothesis."
- "This is a general design heuristic, not a verified source-backed claim."
- "This requires user notes or legal evidence before promotion."
- "This can be used as a diagnostic question, not as proven doctrine."

## Current Release Boundary

The repository is accepted as a draft/source-governed Game Design Knowledgebase.

It is not accepted as a verified source-backed masterclass until evidence records, legal sidecars, user notes, or open/official sources support the claims.
