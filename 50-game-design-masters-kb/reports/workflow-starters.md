# Workflow Starters

Use these cross-phase starter bundles when you want to begin from a real task instead of browsing card by card.

## Spec Pack

Cross-phase bundle for turning a game idea into a structured design and implementation spec.

- Ready file: `knowledge/50-game-design-masters-kb/normalized/packs/spec-pack-ready-to-run.md`
- Starter prompt: `knowledge/50-game-design-masters-kb/normalized/packs/spec-pack-starter-prompt.md`
- Full pack: `knowledge/50-game-design-masters-kb/normalized/packs/spec-pack.md`
- Prompt templates: 5
- Checklists: 2
- Covered phases: 立项与方向 / 核心玩法与系统设计 / 数值与经济设计 / 开发实现 / 美术、UI、体验表达

### When To Use

Use this when you need to align direction, lock the gameplay frame, and turn it into an executable implementation plan.

### Inputs To Prepare

- One-sentence pitch and project identity
- Target players, market, and reference titles
- Core loop assumptions and economy goals
- Platform, scope, and team constraints

### Suggested Workflow

1. Start with direction framing and core loop definition.
2. Resolve the economy and scope assumptions before implementation detail.
3. Turn the approved design into a technical spec and HUD structure.
4. Finish with MVP trimming and implementation review.

## Audit Pack

Cross-phase bundle for status review, risk discovery, regression checking, and delivery-quality audits.

- Ready file: `knowledge/50-game-design-masters-kb/normalized/packs/audit-pack-ready-to-run.md`
- Starter prompt: `knowledge/50-game-design-masters-kb/normalized/packs/audit-pack-starter-prompt.md`
- Full pack: `knowledge/50-game-design-masters-kb/normalized/packs/audit-pack.md`
- Prompt templates: 2
- Checklists: 5
- Covered phases: 测试、验收与审计 / 开发实现 / 美术、UI、体验表达 / 立项与方向

### When To Use

Use this when a build feels unstable, unclear, late, or over-scoped and you need a structured review pass.

### Inputs To Prepare

- Current build or branch state
- Known blockers, bugs, and risk areas
- Recent regressions or quality complaints
- Performance, UI, or onboarding pain points

### Suggested Workflow

1. Run a project-status audit to expose the current bottlenecks.
2. Triage the known bugs and regression risk first.
3. Review build acceptance, performance, and readability together.
4. End with a concrete risk list and a fix order.

## Prototyping Pack

Cross-phase bundle for validating a concept quickly through loop design, prototype implementation, and playtest framing.

- Ready file: `knowledge/50-game-design-masters-kb/normalized/packs/prototyping-pack-ready-to-run.md`
- Starter prompt: `knowledge/50-game-design-masters-kb/normalized/packs/prototyping-pack-starter-prompt.md`
- Full pack: `knowledge/50-game-design-masters-kb/normalized/packs/prototyping-pack.md`
- Prompt templates: 5
- Checklists: 2
- Covered phases: 立项与方向 / 核心玩法与系统设计 / 开发实现 / 测试、验收与审计

### When To Use

Use this when the project is still proving whether the core idea is worth scaling up.

### Inputs To Prepare

- Core fantasy and target player
- Single mechanic or loop hypothesis
- Prototype platform and implementation constraints
- Playtest questions you need answered

### Suggested Workflow

1. Frame the direction and define the smallest fun loop.
2. Pick the one mechanic or interaction the prototype must prove.
3. Build only the minimum playable implementation.
4. Use the testing card to define what success or failure means.

Cross-phase bundle for preparing a playable release candidate, external messaging, and post-launch planning.

- Ready file: `knowledge/50-game-design-masters-kb/normalized/packs/release-pack-ready-to-run.md`
- Starter prompt: `knowledge/50-game-design-masters-kb/normalized/packs/release-pack-starter-prompt.md`

- Prompt templates: 3
- Checklists: 3
- Covered phases: 运营与发布 / 测试、验收与审计 / 立项与方向

### When To Use

Use this when a project is moving from internal development into public testing, store presence, or release preparation.

### Inputs To Prepare

- Target release window and platform set
- Current build quality and known defects
- Store-facing fantasy, hook, and audience
- Retention goals and live-ops expectations

1. Validate the release target and platform fit first.
2. Run pre-release and build-acceptance checks before marketing polish.
3. Write store copy and retention framing against the real build.
4. Close with a concrete post-launch update roadmap.

Cross-phase bundle for worldbuilding, dialogue, quest text, and narrative structure reviews.

- Ready file: `knowledge/50-game-design-masters-kb/normalized/packs/narrative-pack-ready-to-run.md`

- Prompt templates: 2
- Checklists: 2
- Covered phases: 内容与叙事

### When To Use

Use this when story content exists but lacks a clear structure, tone, or production-ready text workflow.

### Inputs To Prepare

- World premise and role of the player
- Main cast, faction, or conflict outline
- Narrative format and delivery constraints
- Samples of current dialogue or quest text

### Suggested Workflow

1. Establish the world and narrative frame first.
2. Write dialogue only after the structure and role logic are stable.
3. Review quest text and narrative beats as production outputs.
4. Use the final checklist to catch inconsistency and readability drift.

## Balance Pack

Cross-phase bundle for economy architecture, combat numbers, reward logic, and balance review loops.

- Ready file: `knowledge/50-game-design-masters-kb/normalized/packs/balance-pack-ready-to-run.md`
- Starter prompt: `knowledge/50-game-design-masters-kb/normalized/packs/balance-pack-starter-prompt.md`
- Full pack: `knowledge/50-game-design-masters-kb/normalized/packs/balance-pack.md`
- Prompt templates: 4
- Checklists: 3
- Covered phases: 数值与经济设计

### When To Use

Use this when the game has enough systems to show inflation, dead rewards, or unclear progression pressure.

### Inputs To Prepare

- Key currencies and resource flows
- Combat stats and progression targets
- Reward tables, drop logic, or progression pacing
- Current balance pain points or telemetry symptoms

### Suggested Workflow

1. Map the economy layers before touching individual numbers.
2. Separate currency roles from combat-balance roles.
3. Review growth curve and reward logic after the system frame is clear.
4. End with the smallest set of balance changes worth testing next.
