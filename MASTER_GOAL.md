# Master Goal

Date: 2026-04-29

## Purpose

The Game Design Knowledgebase exists to make AI reason, question, teach, critique, and plan like a game design master while staying honest about source basis, confidence, and evidence limits.

This is a knowledgebase, not an application. Its value is in structured game design knowledge that can be retrieved, combined, audited, and used by AI to produce design questions, lenses, workflows, lessons, checklists, and decision-support artifacts.

## Current Refocus

The current phase is the Master Framework Phase.

The immediate goal is not Evidence Phase 3 Game Feel intake. Game Feel remains an important domain, but it is not the default next step because the user has not supplied reading notes, legal sidecars, project context, or playtest evidence.

The immediate goal is not ProjectOverlay or PlaytestLog construction. Those require a real game project, and the user has not started an active project yet.

The immediate goal is not evidence ingestion. Evidence intake remains available, but the user has not yet supplied manual reading notes or legal evidence packets.

The immediate goal is to organize the whole field of game design into AI-usable master capabilities.

## What The Project Should Become

The KB should become an AI Game Design Master Framework that can:

- understand the major domains of game design;
- ask expert diagnostic questions;
- choose relevant lenses and workflows for a design problem;
- teach core concepts progressively;
- produce design artifacts such as briefs, audits, decision matrices, loop maps, system maps, playtest plans, and pitch outlines;
- identify evidence gaps and confidence limits;
- avoid pretending that draft scaffolds are verified source-backed doctrine;
- route future user reading notes, project cases, and playtest records into the right knowledge structures.

## What The Project Is Not

This project is not BookOS.

This project is not a reading notes app.

This project is not a personal book tracker.

This project is not a forum platform.

This project is not a full-stack application.

This project is not just evidence intake.

This project is not currently project-based, because no active game project has been supplied.

This project is not currently Game Feel specific.

## Master Framework Outcome

After this phase, a user should be able to ask the AI:

- Help me define a game idea.
- Review this mechanic using expert lenses.
- Diagnose whether my choices are meaningful.
- Map this system and identify runaway loops.
- Teach me the foundations of game design.
- Ask me the questions a senior game director would ask.
- Produce a workflow for a prototype, playtest, economy audit, UI feedback audit, or pitch.
- Tell me which claims are draft and what evidence is missing.

The AI must answer with source-governed confidence boundaries, not false certainty.
